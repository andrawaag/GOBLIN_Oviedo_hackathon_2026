Rendering SSSOM mappings as RDF named graphs & RDF 1.2

Two faithful RDF serializations of ontology mappings — and a live SPARQL view over them.

1 What is SSSOM?

SSSOM — the Simple Standard for Sharing Ontological Mappings — is a lightweight standard for publishing mappings between ontology terms (e.g. MONDO:0000001 ↔ DOID:4). Its native serialization is a hybrid of TSV and YAML: a TSV table is the main payload, and the mapping-set metadata is a YAML block carried in the TSV's leading comment (#) lines.

# mapping_set_id: https://w3id.org/commons/ols/mappings/mondo.ols.sssom.tsv   ← YAML header
# mapping_set_confidence: '0.7'
# curie_map:
#   MONDO: http://purl.obolibrary.org/obo/MONDO_
#   DOID:  http://purl.obolibrary.org/obo/DOID_
subject_id   predicate_id          object_id   mapping_justification        ← TSV table
MONDO:0000001  oboInOwl:hasDbXref  DOID:4      semapv:UnspecifiedMatching

2 Two renderings — the design choice

A mapping is, ontologically, a statement about a statement. The two RDF approaches attach that metadata at different layers of the RDF stack:

Named graphs · TriG

RDF 1.1 dataset / context layer → quads
  • Granularity: one named graph per mapping_set (graph IRI = mapping_set_id)
  • Carries: set-level provenance (source, confidence) on the graph
  • Semantics: dataset semantics undefined by spec → provenance is a convention
  • Tooling: universal — plain SPARQL 1.1 GRAPH ?g {…}
  • Trade-off: per-mapping justification is not attached
  • Models: sssom:MappingSet

RDF 1.2 · Turtle-star

abstract-syntax layer → triple terms
  • Granularity: per mapping — each triple annotated {| … |}
  • Carries: justification + subject/object labels per mapping — lossless
  • Semantics: defined; triple term is opaque & non-asserting (rdf:reifies)
  • Tooling: needs an RDF-star engine (rdflib can't even parse it — Oxigraph can)
  • Trade-off: ~5× statement blow-up (6.2M → 34M)
  • Models: sssom:Mapping
Key insight: named graph ↔ MappingSet, triple term ↔ Mapping. They model different layers — so they compose rather than compete. The named-graph file is the portable, partition-by-source view; the RDF 1.2 file is the lossless, per-mapping master.

4 Live view — Comunica over a SPARQL endpoint

Comunica is a modular SPARQL engine that runs in the browser. It can't hold 5 GB of RDF itself — instead it queries a SPARQL endpoint (your Oxigraph, see §5) and can federate across several (e.g. OLS + Wikidata). Point it at your endpoint and run:

idle

5 Why Oxigraph

Oxigraph is the store that makes this work, for three reasons: (1) it natively parses and queries RDF 1.2 / RDF-star — most stores (and rdflib) cannot; (2) it's a Rust engine fast enough to load the multi-GB files; (3) it serves a standard SPARQL endpoint that Comunica queries. Spin it up:

# install
cargo install oxigraph-cli       # or: pip install pyoxigraph / docker pull ghcr.io/oxigraph/oxigraph

# load the named-graph rendering (quads → dataset)
oxigraph load   --location ./data --file sssom_all.trig
# …or the RDF 1.2 rendering into a separate store (Oxigraph keeps the triple terms)
oxigraph load   --location ./data-star --file sssom_all.ttls

# serve a SPARQL endpoint (CORS-enabled) at http://localhost:7878/query
oxigraph serve  --location ./data --bind 127.0.0.1:7878
